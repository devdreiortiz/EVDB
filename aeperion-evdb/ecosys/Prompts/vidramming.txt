# VIDRAMMING — Concepto completo

---

## Lo que estás describiendo en términos precisos

VIDRA tiene el contexto.
VIDRAMMING lo convierte en movimiento.

No es un generador de videos. Es un **sistema de producción audiovisual por fases** donde cada iteración tiene un único trabajo y no puede hacer el del siguiente.

El problema que resuelve es el mismo que RANDORANIC resolvió para webs:

> Un LLM al que le pides "haz un video de presentación de marca" divide su atención entre animación, timing, narrativa, estética y código al mismo tiempo. El resultado es promedio en todo.

VIDRAMMING fuerza una cosa a la vez. Cinco veces.

## PLANTILLA 1 — Presentación de Marca

La plantilla es el ADN del video. Define todo lo que no cambia antes de empezar.

```
PLANTILLA: Presentación de Marca
DURACIÓN TOTAL: 20 segundos
TONO: Profesional + cercano
PROPÓSITO: Que el espectador sepa quién es la empresa 
           y sienta que vale la pena conocerla más
ESCENAS ESTÁNDAR: 4-6
DENSIDAD DE INFORMACIÓN: baja (impacto, no datos)
RITMO: progresivo — empieza lento, termina con energía
```

## FASE 1 — Reglas de Producción

**Un trabajo:** Extraer lo que se necesita del contexto VIDRA y fijar todas las reglas antes de que exista una sola línea de código.

**Prompt:**
```
Contexto VIDRA disponible: [00_contexto_permanente.md]
Plantilla activa: [presentacion-de-marca.md]

EXTRACCIÓN DE ACTIVOS:
Del contexto de la empresa, extrae SOLO lo útil para esta plantilla:

IDENTIDAD VERBAL:
- Nombre exacto de la empresa
- Slogan (si existe)
- Propuesta de valor en máximo 8 palabras
- 1 logro o hito que genere credibilidad
- Tono de voz definido en brandbook

IDENTIDAD VISUAL:
- Colores primarios (hex)
- Colores secundarios (hex)
- Tipografía principal
- Tipografía secundaria (si existe)
- Logo disponible: sí/no + formato
- Imágenes disponibles: lista

Si algún activo no existe en VIDRA:
ACTIVO FALTANTE: [X]
ALTERNATIVA: [cómo resolverlo sin ese activo]

---

REGLAS DE PRODUCCIÓN:

ASPECTO:
¿Dónde se va a publicar este video?
→ 1:1    (Instagram feed, LinkedIn)
→ 9:16   (Stories, Reels, TikTok)
→ 16:9   (YouTube, presentaciones, web)
[seleccionar uno]

ENTORNO DE EJECUCIÓN:
→ SCPK Mobile  (optimizado para touch, viewport móvil)
→ VS Code Desktop  (optimizado para pantalla grande, precisión)
[seleccionar uno]

ESTILO VISUAL DEL CANVAS:
Combina: [estilo de la plantilla] + [branding de la empresa]
Define:
- Fondo dominante: color sólido / gradiente / oscuro / claro
- Estilo tipográfico: geométrico / orgánico / minimalista / bold
- Estilo de animación: suave / dinámico / cinematográfico / técnico
- Densidad visual: limpio (mucho espacio) / rico (más elementos)
- Paleta activa: [máximo 3 colores que se usarán en el canvas]

OUTPUT: fase1_reglas.md con todo lo anterior fijado.
Nada puede cambiar después de esta fase.
```

## FASE 2 — Timeline

**Un trabajo:** Decidir cuántas escenas hay, cuánto dura cada una, y qué muestra cada una. Sin diseñar nada todavía.

**Prompt:**
```
Reglas de producción: [fase1_reglas.md]
Duración total: 20 segundos

Distribuye el tiempo en escenas.

Para cada escena define:

ESCENA [N]:
DURACIÓN: [X segundos]
TIEMPO DE ENTRADA: [segundo X del video]
TIEMPO DE SALIDA: [segundo X del video]
PROPÓSITO NARRATIVO: [qué debe lograr esta escena en el espectador]
CONTENIDO PRINCIPAL: [qué elemento domina — texto / imagen / logo / dato]
CONTENIDO SECUNDARIO: [qué acompaña al elemento principal]
EMOCIÓN OBJETIVO: [qué debe sentir el espectador al ver esta escena]
NIVEL DE ENERGÍA: 1-5 [1=calmo, 5=impactante]

REGLAS DE TIMELINE:
- La primera escena tiene máximo 3 segundos
  (el espectador decide si sigue en los primeros 2)
- El nivel de energía debe ser progresivo
- La última escena siempre termina con CTA o logo
- No puede haber dos escenas consecutivas con el mismo contenido dominante

OUTPUT: fase2_timeline.md
Una tabla visual del video completo.
```

**Output esperado:**
```
TIMELINE — Presentación de Marca [Empresa X]
Duración total: 20s

[00s-03s] ESCENA 1 — Apertura
Contenido: Logo + tagline
Energía: 2 — entrada suave
Emoción: reconocimiento, curiosidad

[03s-08s] ESCENA 2 — Propuesta de valor  
Contenido: Texto impacto ("Lo que hacemos y por qué importa")
Energía: 3
Emoción: comprensión, interés

[08s-13s] ESCENA 3 — Credibilidad
Contenido: Dato o logro ("X años / X clientes / X proyectos")
Energía: 3
Emoción: confianza

[13s-18s] ESCENA 4 — Diferenciación
Contenido: Lo que solo esta empresa hace
Energía: 4
Emoción: interés elevado

[18s-20s] ESCENA 5 — Cierre
Contenido: Logo + contacto o CTA
Energía: 5 — impacto final
Emoción: recordación, acción
```

## FASE 3 — Construcción de Escenas (1 por 1)

**Un trabajo:** Construir una escena a la vez. Cuando termina una, empieza la siguiente. Nunca dos al mismo tiempo.

**Cada escena es un archivo independiente.**

**Prompt por escena:**
```
Escena a construir: ESCENA [N]
Timeline definido: [fase2_timeline.md]
Reglas de producción: [fase1_reglas.md]
Escenas anteriores completadas: [lista]

CONSTRUYE SOLO ESTA ESCENA.

ESTRUCTURA DEL CANVAS:
Define la composición visual en texto primero:
- ¿Qué ocupa el centro?
- ¿Qué está en los márgenes?
- ¿Hay fondo animado o estático?
- ¿Cuántos elementos hay en pantalla simultáneamente?

ANIMACIÓN DE ENTRADA:
¿Cómo aparecen los elementos?
(fade / slide / scale / reveal / typewriter / etc.)
Define timing de cada elemento: elemento X aparece en segundo Y de la escena

ANIMACIÓN EN ESCENA:
¿Hay movimiento mientras la escena está activa?
(elemento que flota / texto que pulsa / fondo que respira / nada)

ANIMACIÓN DE SALIDA:
¿Cómo desaparece esta escena?
NO definas la transición — eso es fase 4.
Solo define cómo termina internamente esta escena.

DIFERENCIACIÓN DE ESCENA ANTERIOR:
¿Qué hace que esta escena se sienta diferente a la anterior?
[cambio de color de fondo / cambio de densidad / cambio de ritmo]

Luego escribe el código HTML/CSS/JS para esta escena únicamente.

REGLAS DE CÓDIGO:
- Canvas API o CSS animations (decidir en fase 1 y mantener)
- Sin dependencias externas excepto fuentes de Google Fonts
- La escena debe funcionar aislada antes de conectarse
- Duración hardcodeada según timeline
- Comentarios en código indicando qué hace cada bloque

OUTPUT: escena-0[N].html — funcional, aislada, revisable.
```

## FASE 4 — Transiciones

**Un trabajo:** Conectar escenas. La transición no es un efecto decorativo. Es el puente narrativo entre dos momentos emocionales distintos.

**Cada transición es un archivo independiente.**

**Prompt por transición:**
```
Escena de origen: ESCENA [N] — [propósito narrativo]
Escena de destino: ESCENA [N+1] — [propósito narrativo]

ANÁLISIS DE TENSIÓN:
¿Qué cambió entre estas dos escenas?
- Nivel de energía: [N1] → [N2]
- Emoción objetivo: [emoción A] → [emoción B]
- Contenido dominante: [tipo A] → [tipo B]

La transición debe resolver esa tensión.
No puede ser neutral si la tensión es alta.

TIPOS DE TRANSICIÓN DISPONIBLES:
→ Morph: un elemento de la escena A se transforma en un elemento de la escena B
→ Wipe: la escena B entra desde un borde mientras A sale por el opuesto
→ Flash: frame blanco o negro brevísimo entre escenas
→ Scale: la escena A se aleja o acerca hasta revelar la escena B
→ Color shift: el fondo cambia de color como puente entre escenas
→ Particle dissolve: la escena A se fragmenta y los fragmentos forman la B

Selecciona la transición que corresponde a la tensión detectada.
Justifica en una línea.

DURACIÓN DE LA TRANSICIÓN:
Entre 0.3s y 0.8s máximo.
(Las transiciones largas destruyen el ritmo)

Escribe el código de la transición como módulo independiente
que recibe la escena A y la escena B como parámetros.

OUTPUT: transicion-0[N]-0[N+1].js
```

## FASE 5 — Deploy

**Un trabajo:** Ensamblar todo, hacer el pase estético final y ejecutar en navegador.

**Prompt:**
```
Escenas completadas: [escena-01 a escena-0N]
Transiciones completadas: [transicion-01-02 a transicion-0N-1-0N]
Reglas de producción: [fase1_reglas.md]

ENSAMBLAJE:
Construye el archivo index.html final que ejecuta:
escena1 → transicion1-2 → escena2 → transicion2-3 → escena3... 

PASE ESTÉTICO GENERAL:
Revisa el video completo y corrige:

1. CONSISTENCIA TIPOGRÁFICA
   ¿Los tamaños de texto son coherentes entre escenas?
   ¿Los pesos tipográficos siguen jerarquía?

2. CONSISTENCIA DE COLOR
   ¿La paleta de 3 colores se respetó en todas las escenas?
   ¿Hay algún color que apareció y no debería?

3. RITMO GENERAL
   ¿El video tiene sensación de progresión?
   ¿Hay alguna escena que se siente fuera de ritmo?

4. LEGIBILIDAD
   ¿Todo el texto es legible en el aspecto definido?
   ¿Hay texto que aparece y desaparece demasiado rápido?

5. PESO DEL ARCHIVO
   ¿Hay assets que podrían optimizarse?
   ¿El video corre a 60fps sin drops?

CORRECCIONES:
Lista cada corrección hecha con su justificación.

EJECUCIÓN:
index.html listo para abrir en navegador.
Sin dependencias externas.
Auto-ejecutable al abrir.
Loop: sí/no (definido en plantilla)

OUTPUT: 
/fase5_deploy/index.html
/fase5_deploy/correcciones.md
```

## Las plantillas que le siguen a Presentación de Marca

Cada una tiene sus propias reglas base:

```
PLANTILLA 2 — Lanzamiento de Producto
Duración: 30s
Tono: energético + exclusivo
Estructura: problema → solución → producto → CTA
Diferencial: el producto debe verse en movimiento

PLANTILLA 3 — Testimonio de Cliente
Duración: 15s
Tono: humano + auténtico
Estructura: quién es → qué dice → resultado
Diferencial: debe sentirse real, no corporativo

PLANTILLA 4 — Anuncio de Evento
Duración: 10s
Tono: urgente + exclusivo
Estructura: qué es → cuándo → dónde → actúa ya
Diferencial: el countdown o la fecha debe ser protagonista

PLANTILLA 5 — Cultura de Empresa
Duración: 25s
Tono: íntimo + inspirador
Estructura: por qué existimos → cómo trabajamos → únete
Diferencial: las personas son el contenido, no el producto

PLANTILLA 6 — Dato Impacto
Duración: 8s
Tono: contundente + directo
Estructura: número → contexto → logo
Diferencial: un solo dato. nada más.
```

## Lo que hace a VIDRAMMING distinto

Sin él: *"Hazme un video de presentación de marca"* → el LLM diseña, anima, codea y narra al mismo tiempo. Resultado mediocre en todo.

Con él: la Fase 3 usa el 100% de su capacidad en construir una sola escena. La Fase 4 usa el 100% de su capacidad en una sola transición. La Fase 5 usa el 100% en corregir, no en crear.

**Cada fase agota su trabajo antes de pasar al siguiente.**
